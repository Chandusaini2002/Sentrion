# --- Password hashing (prep for JWT auth stage) ---
# passlib 1.7.4 (the latest release — the project is effectively
# unmaintained) reads `bcrypt.__about__.__version__` to detect the
# backend's version. bcrypt 4.1+ removed that attribute entirely, which
# makes passlib log "(trapped) error reading bcrypt version" and then
# mis-handle its own >72-byte safety check, raising
# `ValueError: password cannot be longer than 72 bytes` even for short
# passwords. Pinning bcrypt to the last 4.0.x release (still has
# __about__, still enforces the real 72-byte bcrypt limit correctly)
# restores correct behavior without touching any hashing logic. See
# backend/README.md → Troubleshooting for the full explanation.
passlib[bcrypt]>=1.7.4,<2.0
bcrypt==4.0.1
