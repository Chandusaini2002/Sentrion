# Sentrion — CP PLUS NVR + MediaMTX live streaming

This stage is for **authenticated users only**. Public visitors keep the existing six demo cameras and looping sample footage.

## What this stage adds

- CP PLUS DVR/NVR setup with a known camera count (default: 4).
- Parallel RTSP testing of NVR channels.
- Selection and naming of each working channel before saving.
- One Sentrion `Camera` record per selected NVR channel.
- Camera RTSP URL and credentials remain encrypted in PostgreSQL.
- MediaMTX path registration is done server-side; credentials never go to the browser.
- Live Monitoring embeds MediaMTX WebRTC for logged-in cameras.
- HLS fallback URLs are also generated by the backend for future player work.

## Local development requirements

Install FFmpeg and MediaMTX:

```bash
brew install ffmpeg mediamtx
```

Check both:

```bash
ffprobe -version
mediamtx --version
```

## Backend `.env`

Keep your existing database/security settings and add:

```env
MEDIAMTX_API_URL=http://127.0.0.1:9997
MEDIAMTX_WEBRTC_URL=http://127.0.0.1:8889
MEDIAMTX_HLS_URL=http://127.0.0.1:8888
```

Do **not** regenerate `CAMERA_ENCRYPTION_KEY` for an existing database.

## Run the three services

### Terminal 1 — MediaMTX

From the Sentrion project root:

```bash
mediamtx mediamtx/mediamtx.yml
```

The Sentrion configuration enables:

- Control API: `127.0.0.1:9997`
- HLS: `:8888`
- WebRTC: `:8889`
- WebRTC UDP: `:8189`

### Terminal 2 — FastAPI

```bash
cd backend
source .venv/bin/activate
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Terminal 3 — React/Vite

```bash
cd frontend
npm ci
npm run dev
```

Open `http://localhost:5173` and sign in.

## Add the 4-camera CP PLUS NVR

Go to **Cameras → Add camera** and select **CP PLUS DVR / NVR**.

Example:

- Recorder/site name: `Office NVR`
- Location: `Office`
- Recorder IP: `192.168.1.245`
- RTSP port: `554`
- Connected camera channels: `4`
- Stream: `Sub stream`
- Username/password: the NVR viewer credentials

Click **Test NVR channels**.

Sentrion probes these RTSP paths in parallel:

```text
/cam/realmonitor?channel=1&subtype=1
/cam/realmonitor?channel=2&subtype=1
/cam/realmonitor?channel=3&subtype=1
/cam/realmonitor?channel=4&subtype=1
```

Working channels become selectable. Rename them, for example:

- CH1 → Front Gate
- CH2 → Parking
- CH3 → Office
- CH4 → Back Gate

Then click **Add 4 selected cameras**.

## Live Monitoring

Open **Live Monitoring** and select one of the saved cameras. FastAPI registers a private RTSP source with the local MediaMTX Control API and returns only a browser-safe WebRTC URL.

Data flow:

```text
CP PLUS NVR channel
       ↓ RTSP
MediaMTX (server side)
       ↓ WebRTC
Sentrion browser
```

The camera username/password never appear in the frontend response.

## Browser codec note

For the most reliable Chrome/Safari/Firefox live view, configure the NVR **sub stream as H.264**. MediaMTX routes media but does not transcode codecs. If the scan reports H.265/HEVC and the WebRTC pane stays blank, change that NVR channel's sub-stream codec to H.264 and test again.

## If Live Monitoring says MediaMTX is not reachable

Check:

```bash
curl http://127.0.0.1:9997/v3/config/global/get
```

If it fails, start MediaMTX again:

```bash
mediamtx mediamtx/mediamtx.yml
```

## No database migration

This stage derives each MediaMTX path from the existing camera UUID, so no new database columns are required.

## Current limitation

Channel testing is RTSP probing, not ONVIF discovery. The user tells Sentrion how many NVR channels are expected (for the current customer: 4), and Sentrion tests channels 1 through 4. Automatic ONVIF channel discovery can be added in a later stage.
